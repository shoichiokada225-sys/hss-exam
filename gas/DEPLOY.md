# GAS 再デプロイ手順（2026-08-27 版・所要5分）

`gas/Code.gs` を更新しました。**反映には社長による再デプロイが必要**です（Claudeはデプロイできません）。

## 今回やらないとどうなるか

アプリ側（GitHub Pages）は 2026-08-27 に公開済みですが、GASが旧版のままだと**次の記録がスプレッドシートに入りません**。

| 機能 | 旧GASのまま | 再デプロイ後 |
|---|---|---|
| 離脱回数・離脱秒数・離脱内訳（⚠時刻逆行を含む） | ❌ 記録されない | ✅ K・L・M列 |
| 検算（得点の改ざん検出） | ❌ | ✅ N列 |
| 重複（同名同日の二重受験） | ❌ | ✅ O列・受験意志確認シートは G列 |
| 混雑時のbusy応答（150人一斉終了の詰まり回避） | ❌ 例外扱い | ✅ |
| 氏名の数式インジェクション対策 | ❌ | ✅ |

※ アプリ自体は旧GASでも安全に動きます（得点・氏名・時刻の記録は従来どおり）。壊れるのではなく、**新しい列が空のまま**になります。

## 手順

### 0. コードをクリップボードにコピー（推奨）

326行を手で選択するとコピー漏れが起きます。次を実行するとクリップボードに全文が入ります。

```
powershell -NoProfile -ExecutionPolicy Bypass -File "$HOME\hss-exam\gas\copy-to-clipboard.ps1"
```

`CODE_VERSION : 2026-08-27` と表示されればコピー成功です。

（手動でやる場合は `C:\Users\so\hss-exam\gas\Code.gs` をメモ帳等で開いて Ctrl+A → Ctrl+C）

### 1. Apps Script エディタを開く

**https://script.google.com/home/my**

（`/home/projects` は存在しないURLです。`/home` `/home/my` `/home/all` が有効）

一覧から **HSS試験のプロジェクト** を開きます。

**開けない・一覧に無い場合**、原因はほぼアカウント違いです。GASは**個人Gmailアカウント**でデプロイされています。

1. **アカウントを指定して開く**（複数のGoogleアカウントにログインしている場合）
   - https://script.google.com/u/0/home/my （1つ目のアカウント）
   - https://script.google.com/u/1/home/my （2つ目）
   - https://script.google.com/u/2/home/my （3つ目）
   - 右上のアイコンで、`so@oikk.co.jp` ではなく**個人Gmail**に切り替える

2. **スプレッドシートから辿る（最も確実）**
   - 記録用スプレッドシート（`HSS試験記録_2026` 等）を開く
   - メニュー「**拡張機能**」→「**Apps Script**」
   - ※コンテナバインド型ならこの経路でしか一覧に出ないことがあります

3. **Google ドライブで探す**
   - https://drive.google.com で `HSS` と検索
   - 種類が「Google Apps Script」のファイルを開く

### 2. コードを貼り替えて保存

1. 左のファイル一覧で `Code.gs` を選択
2. エディタ内をクリック → **Ctrl+A**（全選択）→ **Ctrl+V**（貼り付け）
3. **Ctrl+S**（保存）

### 3. 再デプロイ（URLを変えないこと）

1. 右上「**デプロイ**」→「**デプロイを管理**」
2. 既存のウェブアプリ行の **鉛筆アイコン（編集）** をクリック
3. バージョン欄を「**新バージョン**」に変更
4. 「**デプロイ**」をクリック

> 🚨 「**新しいデプロイ**」を選ぶとURLが変わり、`config.js` の `webhookUrl` を書き換えて再pushしない限り**全受験者の結果が届かなくなります**。必ず「デプロイを管理 → 鉛筆 → 新バージョン」の経路で。

- 設定確認: 実行するユーザー=**自分** ／ アクセスできるユーザー=**全員**

### 4. 反映確認（30秒・これで必ず検算する）

ブラウザで次のURLを開きます。

https://script.google.com/macros/s/AKfycbx68TlMXd0nUJ7jzmP5SEcGA0psrzdwDNjE0NcTyZBbzhSqGWUF2ZHESkliBJZRGaKNNw/exec

**成功**（新版が反映された）:
```json
{"status":"ok","service":"HSS Exam Webhook","version":"2026-08-27","columns":15}
```

**まだ旧版**（`version` が無い / 日付が古い）:
```json
{"status":"ok","service":"HSS Exam Webhook"}
```
→ 手順3の「新バージョン」を選び忘れています。もう一度3をやり直してください。

コマンドで確認する場合:
```bash
curl -sL "https://script.google.com/macros/s/AKfycbx68TlMXd0nUJ7jzmP5SEcGA0psrzdwDNjE0NcTyZBbzhSqGWUF2ZHESkliBJZRGaKNNw/exec"
```

### 5. 通しテスト（本番前に1回だけ）

1. 本番アプリ https://shoichiokada225-sys.github.io/hss-exam/ で**本試験**を1人分受験（デモではなく本試験フローで）
2. 記録用スプレッドシートの `本試験結果` に行が増え、**K〜O列（離脱回数/離脱秒数/離脱内訳/検算/重複）** が埋まっていることを確認
   - 検算列が `OK` になっていること（`不一致` なら要調査）
3. 確認できたらGASエディタで関数 `purgeTestRows` を選んで「実行」→ テスト行を削除

## 日次サマリーメールについて（現在停止中）

> 2026-08-19 実測: 08-03に「停止」と判断したがコメントを書き換えただけで、**Google側のトリガーは生存**していた（08-05〜08-18まで毎日20:02に配信継続）。
> **教訓: GASトリガーはローカルからもClaudeからも止められない。「停止した」と記録する前に実配信を必ず確認する。**

- 停止方法: 左メニュー「トリガー」→ `sendDailySummary` の「⋮」→「トリガーを削除」
  （または関数 `uninstallDailyTrigger` を実行し、ログの「削除したトリガー数」で確認）
- **再開したい場合**（試験期間だけ結果通知が欲しいなら有効）:
  1. 左メニュー「トリガー（時計アイコン）」→「トリガーを追加」
  2. 関数 `sendDailySummary` / 時間主導型 / 日付ベースのタイマー / 午後8時〜9時
  3. 保存 → 毎日「本日の受験者数・合格/不合格・一覧」が `so@oikk.co.jp` に1通届く

※ 現状、管理者への能動通知は**ゼロ**です。試験当日は「シートを開いて監視」か「このトリガーを一時的に再開」かを事前に決めてください（README の当日運用を参照）。

## 記録シートの列構成（再デプロイ後）

**本試験結果**
| A | B | C | D | E | F | G | H | I | J | K | L | M | N | O |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 氏名 | 受験者日時 | 得点 | 正答率 | 合否 | 所要時間 | 時間切れ | 言語 | ID | サーバー受信時刻 | 離脱回数 | 離脱秒数 | 離脱内訳 | 検算 | 重複 |

**受験意志確認**: 氏名 / 回答 / 受験者日時 / 言語 / ID / サーバー受信時刻 / **重複**
**回答詳細**: ID / 氏名 / 問番号 / カテゴリ / 問題 / 回答 / 正解 / 正誤
　→ **不正解・未回答のみ**記録されます（正解行は得点列と冗長。150人一斉終了時の負荷対策）

既存シートに新しい列見出しは**自動で追加**されます（`ensureExamHeader_`）。手作業は不要で、既存行は空欄のまま・列の並びも変わりません。

## 動作の仕組み（堅牢化のポイント）
- **記録の正本＝スプレッドシート**（個人Gmailの100通/日上限の影響を受けない）
- **LockService** で同時書き込みを直列化（行欠落なし）。待ち超過は例外でなく `busy` 応答
- **submissionId による重複排除**（再送しても二重記録なし）
- クライアントは **JSONP で「記録されたか」を確認 → 未記録なら自動再送**（取りこぼしゼロ）
- 時間切れ組は **0〜180秒のジッター** で送信を分散（一斉終了の詰まり回避）
- 端末側は **localStorage に結果を保持**し、失敗時や再アクセス時に自動再送
